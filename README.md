# 추임새 음성 인식 → 저장 음원 재생

**휴대폰·아이패드의 웹 버튼으로 사용하려면 [웹 실행 안내](WEB_README.md)를 보세요.** `웹실행.command`를 열고 같은 Wi-Fi의 휴대폰으로 접속하면 됩니다. 디자인만 보려면 `화면미리보기.html`을 브라우저로 여세요. 아래는 기존 Mac 터미널 모드 설명입니다.

Apple Silicon Mac용 프로그램입니다. **Silero VAD + MLX Whisper small + Wav2Vec2 목소리 분류**을 사용합니다. API 키·구독은 필요하지 않습니다. 설치와 최초 모델 다운로드에는 인터넷이 필요하며, 준비 후에는 로컬에서 처리합니다.

2026-11-13 실제 실행 로그에서 large-v3-turbo의 인식이 약 7초 걸려 4초 제한으로 재생이 차단된 것을 확인했습니다. 기본 모델을 small로 바꾸고 단어별 시간 정렬 계산을 껐습니다. 모델 변경 후에는 프로그램을 재시작해야 하며, 첫 실행 때 새 모델을 받습니다. small의 실제 속도와 소음 속 정확도는 다시 측정해야 합니다.

현재 활성 단어는 **얼쑤·좋다·잘한다**입니다. 여성으로 추정한 입력에는 `여_단어.wav`, 남성으로 추정한 입력에는 `남_단어.wav`를 재생합니다. 등록하지 않은 발화, 목소리 구분 불가, 해당 음원 없음에는 아무 소리도 재생하지 않습니다.


## 여자·남자 목소리에 따른 반응

`commands.json`에서 `voice_mode: "model"`로 켜져 있습니다. WAV 파일명은 **재생할 음원의 구분**이며 입력 목소리 학습용 녹음이 아닙니다. 별도로 학습된 Wav2Vec2 분류 모델이 입력 음성을 추정합니다.

| 인식 단어 | 남성으로 추정한 입력 | 여성으로 추정한 입력 |
|---|---|---|
| 얼쑤 / 얼수 | 남_얼쑤.wav | 여_얼쑤.wav |
| 좋다 / 조타 / 좋타 | 남_좋다.wav | 여_좋다.wav |
| 잘한다 | 남_잘한다.wav | 여_잘한다.wav |

현재 이 여섯 파일은 모두 준비되어 있습니다. `voice_trigger` 폴더에 넣으세요. 설정은 다음 형식입니다.

```json
"voice_sounds": {
  "male": ["남_얼쑤*.wav"],
  "female": ["여_얼쑤*.wav"]
}
```

`남_얼쑤2.wav`, `여_얼쑤2.wav`처럼 같은 단어의 추가 음원도 실행 시작 시 읽습니다. 실행 중 파일을 추가하거나 수정했다면 다시 실행하세요. 새로운 단어는 `commands`에 직접 등록해야 합니다. 파일이 없는 그룹은 시작 시 경고하며, 해당 목소리 입력에 다른 그룹의 음원을 대신 재생하지 않습니다.

처음 한 번 **설치.command**를 실행한 뒤 **실행.command**를 실행하세요. 목소리 모델은 약 378 MB의 가중치를 별도로 다운로드합니다. 인터넷이 필요하며, 이미 받은 파일은 캐시에서 읽고 누락된 파일만 받습니다. 다운로드 실패 시 파일명과 오류 원인을 알리고 종료합니다. 준비 후에는 로컬 CPU에서 분류하며 음성을 서버에 업로드하지 않습니다. 기존 Whisper와 함께 준비하므로 최초 시작은 오래 걸릴 수 있습니다.

음높이만으로 남녀를 나누지 않습니다. 기존 `남_얼쑤.wav`가 음높이 분석에서 약 270 Hz로 나와 이 방법으로 잘못 분류되는 것을 확인했기 때문입니다. 모델의 `female`/`male`은 추정 라벨이며 실제 성별을 확정하지 않습니다. 모델은 영어 음성용으로 공개되어 있습니다. 제공된 WAV 6개 검사에서 5개가 파일명의 남녀 라벨과 일치했고, `여_잘한다.wav`는 낮은 점수로 구분 불가였습니다. 여러 사람의 실제 마이크 입력·소음·동시 발화에서의 정확도는 아직 검증하지 않았습니다. 두 사람이 동시에 말할 때 음성을 나누는 기능은 없습니다.

- `voice_min_confidence: 0.8`: 분류 점수가 이 값 미만이면 재생하지 않습니다. 점수 0.8이 실제 정답률 80%를 뜻하지는 않습니다.
- `voice_min_seconds: 0.16`: 충분한 크기의 입력 음성이 이 시간보다 짧으면 재생하지 않습니다.
- `voice_mode: "off"`: 목소리 구분을 끄고 기존 `sounds` 설정으로 재생합니다.

터미널에는 `목소리: 여성 추정/남성 추정/구분 불가`, 분류 점수, 선택한 음원 파일명이 표시됩니다. 로그의 `voice`에도 판정이 남습니다. 목소리 분류를 포함한 인식 결과는 발화 종료 후 **10초 안에** 준비되어야 합니다. 수락한 결과는 재생 대기열에 들어가며, 순서와 2초 재생 간격을 지키기 위한 대기는 별도로 최대 60초 허용합니다.

Whisper·마이크 없이 단일 화자 녹음의 목소리 추정만 검사:

```bash
.venv/bin/python voice_trigger.py --inspect-voice '여_얼쑤.wav'
```

이 검사도 목소리 모델 다운로드가 먼저 필요합니다. 실제 운영에서는 재생용 음원뿐 아니라 마이크로 녹음한 남녀 추임새를 사용해 확인하세요.

모델 없이 여성/남성 음원의 연결만 검사:

```bash
.venv/bin/python voice_trigger.py --test '얼쑤' --voice female --no-play
.venv/bin/python voice_trigger.py --test '잘한다' --voice male --no-play
```

텍스트 검사에서는 목소리를 들을 수 없으므로 `--voice`로 수동 지정합니다. 자동 검사와 텍스트 검사는 실제 목소리 분류 정확도나 마이크 응답 속도를 입증하지 않습니다. 기존 `benchmark.py`는 단어 감지 검사이며 목소리 분류 정확도를 별도로 계산하지 않습니다.

사용 모델: [Common-Voice-Gender-Detection](https://huggingface.co/prithivMLmods/Common-Voice-Gender-Detection). 검토한 고정 리비전 `a0f01051e13f3fe6f7afc411ab88cf83bc3fc53a`의 설정·전처리·safetensors 가중치만 받고, Transformers 내장 Wav2Vec2 클래스로 실행합니다.

## 시작

1. **설치.command**를 더블클릭합니다. 라이브러리 설치, 자동 검사, 모델 준비를 순서대로 수행합니다.
2. 설치 성공 안내가 나오면 **실행.command**를 더블클릭합니다.
3. ‘준비 완료’가 나오면 터미널 창을 선택하고 **스페이스바를 누른 채 1초 기다린 뒤 계속 누르면서** 말합니다. ‘마이크 열림’ 안내를 확인하세요. 말을 마치면 손을 떼세요. macOS가 마이크 권한을 요청하면 허용합니다.
4. 종료하려면 터미널에서 **Ctrl+C**를 누릅니다.

`설치.command`는 이 폴더의 `.venv`를 사용합니다. 이 Mac에서 이미 설치된 Anaconda 라이브러리를 재사용하며, 추가 설치는 `.venv`에 수행합니다. 시스템 Python·Anaconda 패키지를 직접 수정하지 않습니다. 새 Mac에서는 Python 3.10 이상이 필요합니다.

설치가 실패하면 ‘설치 완료’로 표시하지 않습니다. 네트워크와 오류를 확인한 뒤 같은 설치 파일을 다시 실행하면 됩니다. **현재 환경에서 확인한 설치 상태와 제한은 [INSTALL_STATUS.md](INSTALL_STATUS.md)를 확인하세요.**

## 스페이스바를 누르고 있는 동안만 마이크 열기

**스페이스바를 누른 채 1초 기다리고, 말하는 동안 계속 누르세요. 손을 떼면 마이크가 닫힙니다.** 실행 터미널 창을 선택한 상태에서 시작하세요. Enter는 필요 없습니다.

1. 실행 직후에는 **마이크 대기 중**이며 실제 마이크 입력 스트림을 열지 않습니다.
2. 스페이스바를 누르고 유지하면 **“계속 누르고 계세요. 1초 후부터 음성 인식을 시작합니다”**라고 안내합니다. 1초 전에 손을 떼면 취소하고 마이크를 열지 않습니다.
3. 1초 뒤 실제 입력 스트림을 열고 **“마이크 열림 — 스페이스바를 누른 상태로 말씀하세요. 손을 떼면 닫힙니다.”**를 표시합니다. 이때부터 말하세요.
4. 누르고 있는 동안은 말 중간에 쉬어도 마이크가 계속 열려 있습니다. 기존의 0.6초 무음 자동 닫기와 10초 무발화 자동 닫기는 사용하지 않습니다.
5. **손을 떼면 마이크 입력 스트림을 닫습니다.** 키를 떼기 전에 캡처한 오디오와, 말 직후 손을 떼어 무음 구간이 없는 마지막 발화도 인식 대상으로 넘깁니다. 이미 진행 중인 인식·재생 대기 결과는 계속 처리합니다. 키 해제는 입력을 끝내는 동작이며 대기 결과를 취소하지 않습니다.
6. 키를 뗀 후 진행·대기 중인 인식이 끝나면 추임새를 순서대로 재생합니다. 다음 발화는 다시 누르고 1초 기다린 뒤 말하세요.

누르고 있을 때 들어오는 반복 공백의 간격으로 해제를 추정하지 않습니다. macOS의 [실제 키 상태 API](https://developer.apple.com/documentation/coregraphics/cgeventsource/keystate%28_%3Akey%3A%29?language=objc)로 눌림·해제를 확인하며, 일반 제어 루프는 약 10ms 간격으로 상태를 확인합니다. 모델 준비 중부터 누르고 있던 키는 한 번 떼고 다시 눌러야 합니다. 누름 시작은 실행 터미널에서 받아야 하며 다른 앱에서 누른 키로 시작하지 않습니다.

음원 재생 중 및 종료 후 0.2초 동안 새로 누른 키는 시작 명령으로 받지 않습니다. 재생이 끝나면 손을 떼고 다시 누르세요. 재생 사이 무음 구간에는 새 입력을 시작할 수 있습니다. 프로그램 종료(Ctrl+C) 또는 오류 시 입력 스트림을 닫고 터미널 키 입력 설정을 복구합니다.

이미 받은 모델만 사용하려면 다음처럼 실행하세요. 이번 키 입력 변경에는 추가 패키지나 모델 다운로드가 필요하지 않습니다.

```bash
HF_HUB_OFFLINE=1 ./실행.command
```

## 터미널 사용

이 폴더에서 아래 명령을 실행합니다.

```bash
./설치.command
./실행.command
```

추가 진단:

```bash
.venv/bin/python voice_trigger.py --doctor
.venv/bin/python voice_trigger.py --prepare
.venv/bin/python voice_trigger.py --list-devices
.venv/bin/python voice_trigger.py --no-play
```

- `--doctor`: 설치 버전, 설정, 장치 확인. 음성 인식 성공 여부는 검사하지 않습니다.
- `--prepare`: VAD 로드와 실제 Whisper 워밍업. GPU를 열 수 없는 환경에서는 실패합니다.
- `--no-play`: 실제 마이크로 인식하되 음원 출력을 생략합니다. 판정 지연은 볼 수 있으나 스피커 출력 지연 측정은 아닙니다.

## 문장 속 추임새·연속 입력·재생 순서

2026-11-17 변경: 발화 전체가 추임새 하나일 필요가 없습니다. 현재 세 명령은 `match: "word"`로 문장 안의 독립 단어를 찾습니다.

| 입력 예시 | 처리 |
|---|---|
| 아 이거 되는건가 얼쑤? | 얼쑤 한 번 |
| 얼쑤 얼쑤 얼쑤 | 얼쑤 한 번 |
| 얼쑤얼쑤얼쑤 | 얼쑤 한 번 |
| 얼쑤, 잘한다, 좋다 | 얼쑤 → 잘한다 → 좋다 순서 |
| 얼쑤라고 말해 봐 / 안좋다 / 잘한다는 말 | 다른 단어의 일부이므로 일치하지 않음 |

- **중복 병합**: 같은 추임새는 한 인식 문장 안에서 한 번만 등록합니다. 별도 발화라도 마지막 같은 추임새의 입력 끝부터 다음 입력 시작까지 5초 미만이면 합칩니다. 반복할 때마다 이 시간이 연장됩니다. 같은 추임새가 이미 재생 대기 중이면 5초가 지나도 추가하지 않습니다. 다른 목소리의 같은 추임새도 합치며, 처음 수락한 목소리의 음원을 유지합니다. 새로 출력하려면 기존 대기가 끝나고 마지막 같은 입력 후 최소 5초를 두세요.
- **재생 간격**: 앞 음원이 끝난 뒤 **2초** 이상 기다린 후 다음 음원을 재생합니다. 시작 시각 사이 2초가 아닙니다. 예를 들어 얼쑤 음원이 3초라면 다음 잘한다는 얼쑤 시작 후 최소 5초 뒤에 시작합니다. 실제 첫 출력 callback의 DAC 예정 종료 시각을 기준으로 계산합니다.
- **연속 발화 수집**: 스페이스바를 누른 동안 발화를 수집하고, 손을 떼어 마이크를 닫은 뒤 진행·대기 중인 인식을 마치면 재생을 시작합니다. 첫 결과가 나왔다고 이어 말하는 발화를 버리지 않습니다. 입력 인식과 재생 대기열은 각각 최대 16개이며, 먼저 들어온 순서를 유지합니다. 가득 차면 새 입력을 버리고 로그를 남깁니다.
- **재생 중 입력**: 스피커 소리의 재인식을 막기 위해 실제 재생 중과 재생 종료 후 0.2초 동안의 마이크 입력은 받지 않습니다. 따라서 서로 다른 추임새도 이 시간에 말하면 누락됩니다. 마이크가 열린 동안 연속해서 미리 말한 추임새와, 재생 사이의 나머지 무음 구간에 스페이스바로 시작한 입력은 순서대로 대기합니다. 키를 누른 채 쉬는 동안에는 재생을 시작하지 않습니다. 손을 떼면 모은 입력을 처리합니다.
- **문장 분할**: 말소리가 끝나면 약 0.32초 뒤 인식에 넘깁니다. 발화 앞부분 약 0.224초를 보존합니다. 긴 문장은 약 5초 단위로 0.384초씩 겹쳐 인식하며, 잘린 구간도 추임새 검색 대상입니다. 겹친 구간의 같은 명령은 중복 정책으로 합칩니다. 단어가 경계에서 잘리거나 음성 인식이 틀리면 놓칠 수 있습니다.
- **품질·목소리 검사**: Whisper의 구간별 로그확률·무음 확률·반복 수치, 목소리 점수와 음원 존재 검사를 통과한 후보만 대기합니다. 한 문장 속 여러 추임새는 해당 발화 전체의 목소리 추정 결과를 공유합니다. 동시에 말한 사람들을 분리하지 않습니다.
- **매칭 범위**: 단어 앞뒤가 공백·문장부호이거나 문장 끝인 경우를 찾습니다. 한글 NFC/NFD와 단어 안의 띄어쓰기 차이를 처리합니다. 유사 문자열 매칭이나 부정 의도 판별은 하지 않습니다. 예를 들어 “얼쑤 하지 마”에도 독립 단어 얼쑤가 있으므로 재생 후보입니다. `match: "exact"`로 바꾸면 해당 명령만 기존의 발화 전체 일치로 제한할 수 있습니다.
- 설정과 음원은 실행 시작 시 읽습니다. **수정 후에는 Ctrl+C로 종료하고 실행.command를 다시 실행하세요.**

VAD는 말소리 검출기이며 주변 사람의 대화를 제거하지 않습니다. 문장 속 단어까지 찾으므로 일반 대화에 등장한 추임새도 반응할 수 있습니다. 발화자가 마이크에 가까이 말하도록 배치하세요.

## 인식 기한·재생 대기와 측정 한계

`max_latency: 10`은 **발화 종료 → 인식·목소리 분류 완료 및 대기열 등록** 기한입니다. 0.05초의 여유를 두며, 오래된 입력은 인식 전과 결과 수락 시 버립니다. 모든 발화를 10초 안에 처리한다는 보장은 아닙니다.

수락된 후보는 `queue_timeout: 60`으로 **수락 시점부터 출력 시작까지 최대 60초** 대기할 수 있습니다. 이 기한은 대기 중과 첫 출력 callback의 DAC 예정 시각에서 확인합니다. 60초를 일부러 채워 기다리지 않습니다. 스페이스바 해제, 선행 인식, 앞 음원의 재생 및 2초 간격이 끝나면 재생합니다. 따라서 뒤쪽 음원은 발화 종료부터 실제 출력까지 10초를 넘을 수 있습니다. Ctrl+C로 종료하면 남은 대기는 폐기합니다.

화면의 `추정 DAC 출력 지연`은 PortAudio가 제공하는 오디오 장치 재생 예정 시각에 근거합니다. 음원 앞의 무음은 메모리에서 줄여 사용하며 원본 파일은 수정하지 않습니다. Bluetooth·외부 스피커·음향 경로의 추가 지연은 완전히 반영되지 않을 수 있습니다. 실제 간격은 유선 출력과 별도 녹음으로 대조하세요.

Whisper 로그확률·무음 확률은 정답 확률이 아닙니다. 기본값인 `word_timestamps: false`에서는 단어별 정렬·확률 계산을 생략하고 구간별 품질 정보로 판정합니다. true로 바꾸면 단어별 확률도 검사하며 추론 시간이 늘 수 있습니다. 텍스트·가상 시간 검사는 실제 소음 속 마이크 인식률을 입증하지 않습니다.

## 단어 추가

`commands.json`의 `commands`에 아래 형식으로 추가합니다. 음원 경로는 이 설정 파일 기준입니다.

```json
{
  "name": "지화자",
  "enabled": true,
  "phrases": ["지화자"],
  "sounds": ["남_지화자.wav"],
  "match": "word",
  "volume": 1.0,
  "cooldown": 0.7
}
```

위 예시의 음원은 제공되어 있지 않습니다. 파일을 직접 넣은 후 등록해야 합니다. 목소리 구분을 켠 상태에서는 아래 설명처럼 `voice_sounds`도 등록하세요. 같은 목소리 그룹에 여러 음원을 등록하면 그중 하나를 고릅니다.

`phrases`에 비슷하게 들리는 말을 많이 넣으면 오작동이 늘 수 있습니다. 실제 오인식 결과를 확인한 표현만 추가하세요. `fallback`은 `null`로 유지하세요. 문장 안에서도 찾으려면 `match`는 `word`, 발화 전체 일치만 허용하려면 `exact`로 설정하세요.

주요 설정:

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `vad_start` / `vad_end` | 0.6 / 0.35 | 말소리 시작·종료 판정 확률 |
| `silence_duration` | 0.32 | 말 끝 확인에 기다리는 초 |
| `max_speech` | 5.0 | 긴 문장을 겹쳐 분할하는 구간 길이 |
| `max_latency` | 10.0 | 발화 종료부터 인식 결과 수락까지의 기한 |
| `duplicate_window` | 5.0 | 같은 추임새 입력을 합치는 시간. 반복 입력 때마다 연장 |
| `playback_gap` | 2.0 | 앞 음원 종료부터 다음 시작까지 최소 간격 |
| `burst_silence` | 0.6 | 이전 자동 닫기 방식의 설정. 현재 키 유지 모드에서는 사용하지 않음 |
| `queue_timeout` | 60.0 | 수락된 후보의 재생 대기 기한 |
| `queue_capacity` | 16 | 인식/재생 대기열 각각의 최대 개수 |
| `min_avg_logprob` | -0.8 | 더 높이면 인식 결과를 더 엄격히 거름 |
| `max_no_speech_prob` | 0.55 | 더 낮추면 무음 추정 결과를 더 엄격히 거름 |
| `word_timestamps` | false | 단어별 정렬·확률 계산. 켜면 추가 추론 시간 필요 |
| `min_word_probability` | 0.35 | word_timestamps가 true일 때만 단어 확률 검사에 사용 |
| `input_device` / `output_device` | null | 기본 장치. 번호 또는 고유하게 일치하는 이름 일부 지정 가능 |
| `event_log` | logs/events.jsonl | 진단 기록 위치. null이면 기록 안 함 |

## 녹음과 자동 검사

모델 없이 텍스트 매칭 확인:

```bash
.venv/bin/python voice_trigger.py --test '아 이거 되는건가 얼쑤?' --voice female --no-play
.venv/bin/python voice_trigger.py --test '얼쑤라고 말해 봐' --no-play
.venv/bin/python voice_trigger.py --type --voice male --no-play
```

녹음 파일의 VAD·인식·판정 확인:

```bash
.venv/bin/python voice_trigger.py --file recordings/test.wav
```

파일 분석은 음원을 출력하지 않습니다. 표시되는 인식 소요시간은 추론 시간이며 실시간 전체 응답 지연이 아닙니다.

정답이 있는 녹음 묶음의 감지율과 오작동 확인:

```bash
.venv/bin/python benchmark.py recordings/manifest.jsonl --report logs/benchmark.json
```

manifest.jsonl 예시 (audio 경로는 manifest 파일 기준):

```jsonl
{"audio":"positive.wav","expected":"얼쑤"}
{"audio":"conversation.wav","expected":null}
```

한 파일에는 대상 추임새가 한 번 있거나 없어야 합니다. 이 검사는 파일 단위 감지·오작동과 추론 시간을 측정하며, 실시간 대기열·스피커 지연은 측정하지 않습니다. 실제 녹음은 포함되어 있지 않습니다.

자동 로직 검사:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

자동 검사는 문장 매칭, 인식 품질 거부, 긴 대화 분할, 유실 구간, 중복·기한·재생음 차단, 리샘플링, 출력 callback을 검사합니다. 실제 소음 속 음성 인식률을 입증하는 검사는 아닙니다.

## 로그·문제 해결

원시 마이크 음성은 저장하지 않습니다. `logs/events.jsonl`에는 인식된 문장, 추론 시간, 판정·누락 원인, 추정 출력 지연이 남습니다. `repeated_interjection`(반복 병합), `deadline`(인식 기한), `playback_queue_expired`/`deadline_at_output`(재생 대기 만료), `recognition_queue_full`/`playback_queue_full`, `input_overflow`를 구분할 수 있습니다. `recognized.commands`에는 한 발화에서 수락한 모든 추임새가 순서대로 기록됩니다.

- Silero가 없다는 오류: 인터넷이 되는 터미널에서 설치.command를 다시 실행합니다.
- Metal 장치가 없다는 오류: GPU에 접근할 수 있는 일반 macOS 터미널에서 실행합니다.
- 오디오 장치가 없다는 오류: 마이크·스피커 연결과 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 터미널 권한을 확인합니다.
- 기한 초과 누락이 많음: 다른 무거운 작업을 종료하고 `--file`로 추론 시간을 확인합니다. 모델을 변경한다면 정확도와 속도를 다시 검증해야 합니다.
- 잘못 재생함: 실제 로그와 녹음을 바탕으로 품질 임곗값과 마이크 위치를 조정합니다. 키워드 별칭을 무작정 늘리지 않습니다.
