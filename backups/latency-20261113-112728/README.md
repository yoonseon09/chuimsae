# 추임새 음성 인식 → 저장 음원 재생

Apple Silicon Mac용 프로그램입니다. **Silero VAD + MLX Whisper large-v3-turbo**를 사용합니다. API 키·구독은 필요하지 않습니다. 설치와 최초 모델 다운로드에는 인터넷이 필요하며, 준비 후에는 로컬에서 처리합니다.

현재 활성 단어는 **얼쑤**입니다. 기존 ‘좋다’ 설정과 음원은 보존하고 비활성화했습니다. 등록하지 않은 발화에는 아무 소리도 재생하지 않습니다.

## 시작

1. **설치.command**를 더블클릭합니다. 라이브러리 설치, 자동 검사, 모델 준비를 순서대로 수행합니다.
2. 설치 성공 안내가 나오면 **실행.command**를 더블클릭합니다.
3. macOS가 터미널의 마이크 권한을 요청하면 허용합니다. ‘준비 완료’가 나온 뒤 발화합니다.
4. 종료하려면 터미널에서 **Ctrl+C**를 누릅니다.

`설치.command`는 이 폴더의 `.venv`를 사용합니다. 이 Mac에서 이미 설치된 Anaconda 라이브러리를 재사용하며, 추가 설치는 `.venv`에 수행합니다. 시스템 Python·Anaconda 패키지를 직접 수정하지 않습니다. 새 Mac에서는 Python 3.10 이상이 필요합니다.

설치가 실패하면 ‘설치 완료’로 표시하지 않습니다. 네트워크와 오류를 확인한 뒤 같은 설치 파일을 다시 실행하면 됩니다. **현재 환경에서 확인한 설치 상태와 제한은 [INSTALL_STATUS.md](INSTALL_STATUS.md)를 확인하세요.**

## 터미널 사용

이 폴더에서 아래 명령을 실행합니다.

```bash
./설치.command
./실행.command
```

추가 진단:

```bash
.venv/bin/python voice_trigger.py --doctor
.venv/bin/python voice_trigger.py --prepare
.venv/bin/python voice_trigger.py --list-devices
.venv/bin/python voice_trigger.py --no-play
```

- `--doctor`: 설치 버전, 설정, 장치 확인. 음성 인식 성공 여부는 검사하지 않습니다.
- `--prepare`: VAD 로드와 실제 Whisper 워밍업. GPU를 열 수 없는 환경에서는 실패합니다.
- `--no-play`: 실제 마이크로 인식하되 음원 출력을 생략합니다. 판정 지연은 볼 수 있으나 스피커 출력 지연 측정은 아닙니다.

## 동작과 오작동 방지

모델·음원 준비 → 마이크 입력 → Silero로 말소리 구간 검출 → Whisper 인식 → 등록 표현 및 품질 확인 → 중복·기한 검사 → 음원 출력 순서입니다.

- ‘얼쑤!’, ‘얼수’처럼 등록 표현 전체가 일치할 때 판정합니다. 공백·문장부호와 한글 조합형 차이는 무시합니다. 유사 문자열 매칭은 하지 않습니다.
- ‘얼쑤라고 말해 봐’, ‘어서 오세요’, ‘얼쑥’, ‘얼쑤 좋다’는 기본 등록 표현과 일치하지 않습니다.
- 키워드 프롬프트를 사용하지 않습니다. 모델이 소음을 등록 단어로 인식하도록 강하게 유도하지 않습니다.
- 발화 앞부분 약 0.224초를 보존하고, 말소리가 끝난 뒤 약 0.32초 기다립니다.
- 긴 대화는 최대 약 2.4초 단위로 겹쳐 나눕니다. **강제로 잘린 구간과 그 발화의 연속 구간은 재생하지 않습니다.** 대화 중 마지막 단어만 추임새로 보이는 오작동을 줄이기 위한 보수적인 동작입니다. 길게 외치는 추임새도 이 제한에 걸릴 수 있습니다.
- 인식은 별도 프로세스 하나에서 수행합니다. 진행 중 작업 외에 대기 발화는 최신 하나만 보관합니다. 대기 중 밀려난 발화는 누락으로 기록합니다.
- 재생 중과 재생 종료 후 0.2초 동안은 발화를 받지 않습니다. 그 시간대의 입력과 이전 인식 결과를 나중에 다시 재생하지 않습니다.
- 설정과 음원은 실행 시작 시 읽습니다. **수정하면 프로그램을 다시 실행하세요.**

VAD는 말소리 검출기이며 주변 사람의 대화를 제거하는 기능은 아닙니다. 발화자가 마이크에 가까이 말하도록 배치하는 것이 유리합니다. 일반 대화에서도 동일한 단어를 독립적으로 말하면 의도를 완벽히 구분할 수 없습니다.

## 4초 기준과 측정 한계

기준은 **추임새 발화 종료 → 출력 시작**입니다. 의도적인 추가 대기는 넣지 않습니다.

대기열·인식 후·첫 출력 callback에서 기한을 검사합니다. 기본 기한은 4초이며 0.05초 여유를 둡니다. 기한이 지난 결과는 재생하지 않고 누락으로 기록합니다. **늦은 재생을 차단하는 것과 모든 발화를 4초 이내에 처리하는 것은 다릅니다.** 처리 성능과 누락률을 실제 장비에서 확인해야 합니다.

화면의 `추정 DAC 출력 지연`은 PortAudio가 제공하는 오디오 장치 재생 예정 시각에 근거합니다. 음원 앞의 무음은 메모리에서 줄여 사용하며 원본 파일은 수정하지 않습니다. Bluetooth·외부 스피커·음향 경로의 추가 지연은 완전히 반영되지 않을 수 있습니다. 실제 상한을 점검할 때는 유선 출력과 별도 녹음을 이용해 발화 끝과 음원 시작을 대조하세요.

Whisper 로그확률·무음 확률·단어 확률은 정답 여부를 보증하는 수치가 아닙니다. 초기 임곗값은 보수적인 시작값이며, 여러 사람의 실제 녹음으로 조정해야 합니다.

## 단어 추가

`commands.json`의 `commands`에 아래 형식으로 추가합니다. 음원 경로는 이 설정 파일 기준입니다.

```json
{
  "name": "지화자",
  "enabled": true,
  "phrases": ["지화자"],
  "sounds": ["남_지화자.wav"],
  "match": "exact",
  "volume": 1.0,
  "cooldown": 0.7
}
```

위 예시의 음원은 제공되어 있지 않습니다. 파일을 직접 넣은 후 등록해야 합니다. 여러 음원을 등록하면 그중 하나를 고릅니다. ‘좋다’는 기존 항목의 `enabled`만 `true`로 바꾸면 됩니다.

`phrases`에 비슷하게 들리는 말을 많이 넣으면 오작동이 늘 수 있습니다. 실제 오인식 결과를 확인한 표현만 추가하세요. `fallback`은 `null`, `match`는 `exact`로 유지해야 합니다.

주요 설정:

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `vad_start` / `vad_end` | 0.6 / 0.35 | 말소리 시작·종료 판정 확률 |
| `silence_duration` | 0.32 | 말 끝 확인에 기다리는 초 |
| `max_speech` | 2.4 | 강제로 분리하는 구간 길이. 긴 발화는 재생 제외 |
| `max_latency` | 4.0 | 출력 시작 기한. 4초보다 크게 설정할 수 없음 |
| `min_avg_logprob` | -0.8 | 더 높이면 인식 결과를 더 엄격히 거름 |
| `max_no_speech_prob` | 0.55 | 더 낮추면 무음 추정 결과를 더 엄격히 거름 |
| `min_word_probability` | 0.35 | 더 높이면 불확실한 단어를 더 엄격히 거름 |
| `input_device` / `output_device` | null | 기본 장치. 번호 또는 고유하게 일치하는 이름 일부 지정 가능 |
| `event_log` | logs/events.jsonl | 진단 기록 위치. null이면 기록 안 함 |

## 녹음과 자동 검사

모델 없이 텍스트 매칭 확인:

```bash
.venv/bin/python voice_trigger.py --test '얼쑤!' --no-play
.venv/bin/python voice_trigger.py --test '얼쑤라고 말해 봐' --no-play
.venv/bin/python voice_trigger.py --type --no-play
```

녹음 파일의 VAD·인식·판정 확인:

```bash
.venv/bin/python voice_trigger.py --file recordings/test.wav
```

파일 분석은 음원을 출력하지 않습니다. 표시되는 인식 소요시간은 추론 시간이며 실시간 전체 응답 지연이 아닙니다.

정답이 있는 녹음 묶음의 감지율과 오작동 확인:

```bash
.venv/bin/python benchmark.py recordings/manifest.jsonl --report logs/benchmark.json
```

manifest.jsonl 예시 (audio 경로는 manifest 파일 기준):

```jsonl
{"audio":"positive.wav","expected":"얼쑤"}
{"audio":"conversation.wav","expected":null}
```

한 파일에는 대상 추임새가 한 번 있거나 없어야 합니다. 이 검사는 파일 단위 감지·오작동과 추론 시간을 측정하며, 실시간 대기열·스피커 지연은 측정하지 않습니다. 실제 녹음은 포함되어 있지 않습니다.

자동 로직 검사:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

자동 검사는 문장 매칭, 인식 품질 거부, 긴 대화 분할, 유실 구간, 중복·기한·재생음 차단, 리샘플링, 출력 callback을 검사합니다. 실제 소음 속 음성 인식률을 입증하는 검사는 아닙니다.

## 로그·문제 해결

원시 마이크 음성은 저장하지 않습니다. `logs/events.jsonl`에는 인식된 문장, 추론 시간, 판정·누락 원인, 추정 출력 지연이 남습니다. `deadline`, `deadline_at_output`, `overload_replaced`, `input_overflow`, `continuous_speech`를 누락 통계로 구분할 수 있습니다.

- Silero가 없다는 오류: 인터넷이 되는 터미널에서 설치.command를 다시 실행합니다.
- Metal 장치가 없다는 오류: GPU에 접근할 수 있는 일반 macOS 터미널에서 실행합니다.
- 오디오 장치가 없다는 오류: 마이크·스피커 연결과 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 터미널 권한을 확인합니다.
- 4초 초과 누락이 많음: 다른 무거운 작업을 종료하고 `--file`로 추론 시간을 확인합니다. 설정의 모델을 작은 MLX Whisper로 바꿀 수도 있으나 정확도와 속도를 다시 검증해야 합니다.
- 잘못 재생함: 실제 로그와 녹음을 바탕으로 품질 임곗값과 마이크 위치를 조정합니다. 키워드 별칭을 무작정 늘리지 않습니다.
