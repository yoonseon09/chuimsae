# 추임새 · 휴대폰 버튼 → Mac 스피커

흰색 전체 화면 중앙의 원을 **누르고 있는 동안만** 휴대폰 마이크를 엽니다. 녹음 중에는 음성을 작은 PCM 조각으로 Mac에 전송합니다. **손을 떼면 마이크를 즉시 닫고**, Mac에서 Whisper 인식·목소리 분류를 실행해 저장된 WAV를 Mac의 기본 출력 장치로 재생합니다.

목표는 **말 끝부터 스피커 출력 시작까지 3초 이내**입니다. 코드는 기한을 넘긴 결과를 재생하지 않습니다. 실제 3초 달성 여부는 휴대폰·Wi-Fi·Mac·스피커를 연결해 측정해야 하며, 기한 초과 차단을 성능 달성으로 계산하지 않습니다.

## 먼저 화면 확인

`화면미리보기.html`을 브라우저로 여세요. 외부 연결 없이 디자인과 원을 누르는 모습을 볼 수 있습니다. 이 파일에서는 실제 녹음·인식·재생을 하지 않습니다.

실제 휴대폰의 마이크와 음성 전송까지만 검사하려면 `웹미리보기.command`를 더블클릭하세요. 아래와 같은 HTTPS 설정이 필요합니다. 이 모드는 원본 음성을 저장하지 않으며, 추임새 인식 결과나 스피커 재생을 가짜로 표시하지 않습니다.

## 휴대폰으로 실행

1. 이전의 `실행.command`는 종료하세요. Mac과 휴대폰을 같은 Wi-Fi에 연결합니다.
2. **`웹실행.command`를 더블클릭**하세요. 기존 `.venv`를 사용하며, 없을 때만 웹 연결 라이브러리 `aiohttp`를 추가합니다. `설치.command`를 실행한 기존 환경이 필요합니다.
3. 터미널에 나오는 **‘처음 한 번 휴대폰 설정’** 주소를 휴대폰에서 여세요. 이 주소는 HTTP이지만 인증서 안내와 공개 인증서만 제공합니다. 녹음 화면과 음성 전송은 HTTPS/WSS를 사용합니다.
4. 기종별 안내에 따라 로컬 인증서를 설치합니다. 이 작업은 휴대폰에서 직접 해야 합니다. Mac의 신뢰 저장소나 휴대폰 설정을 프로그램이 자동으로 바꾸지 않습니다.
5. ‘추임새 열기’를 눌러 녹음 화면으로 이동합니다. Mac 모델 준비가 끝나면 **‘Mac 연결됨’**이 표시됩니다.
6. 원을 누른 채 유지하고, 마이크가 열려 원이 반응하면 “얼쑤”라고 말한 뒤 손을 떼세요. 처음 마이크 권한 창이 떴을 때 손을 뗐다면, 허용 후 원을 다시 눌러야 합니다.
7. Mac에 연결된 스피커에서 음원이 나오는지 확인하세요. 종료는 Mac 터미널의 **Ctrl+C**입니다.

Mac의 사운드 설정에서 사용할 출력 장치를 먼저 선택하세요. `commands.json`의 `output_device`가 지정돼 있다면 그 장치가 우선합니다. macOS 방화벽이 Python의 들어오는 연결을 물으면 같은 Wi-Fi의 휴대폰 연결을 허용해야 합니다. 게스트 Wi-Fi가 기기끼리의 연결을 막는 환경에서는 다른 네트워크를 사용하세요.

서버는 기본 **HTTPS 8765**, 초기 설정은 **HTTP 8766** 포트를 사용합니다. 실행할 때마다 새 연결 키를 만들므로, 재실행 후에는 터미널의 새 접속 주소를 사용하세요. 한 번에 한 기기만 녹음·인식·재생을 담당하며 다른 기기는 대기합니다.

### 아이폰 · 아이패드 인증서

1. 설정 페이지에서 ‘추임새 인증서 프로파일 다운로드’를 누르고 허용합니다.
2. 설정 → 일반 → VPN 및 기기 관리 → **추임새 로컬 HTTPS**를 설치합니다.
3. 설정 → 일반 → 정보 → 인증서 신뢰 설정 → **Chuimsae Local Test Root**의 신뢰를 켭니다.
4. Safari로 설정 페이지에 돌아가 ‘추임새 열기’를 누릅니다.

프로파일은 이 Mac에서 생성한 CA 인증서 1개만 담고 있습니다. VPN·기기 관리·계정 정보는 없습니다. 인증서의 SHA-256 지문은 터미널과 설정 페이지에 표시합니다. 테스트가 끝나면 VPN 및 기기 관리에서 해당 프로파일을 삭제할 수 있습니다. [Apple의 인증서 신뢰 안내](https://support.apple.com/102390)

### 안드로이드 인증서

설정 페이지에서 CA 인증서를 다운로드한 뒤 휴대폰의 ‘인증서 설치’에서 **CA 인증서**로 설치하고 Chrome으로 접속합니다. 예: 설정 → 보안 및 개인정보 보호 → 기타 보안 설정 → 인증서 설치. 제조사와 OS 버전에 따라 경로가 달라집니다. 테스트 후 사용자 인증서에서 제거할 수 있습니다.

### Mac 주소가 다른 경우

실행 시 활성화된 `en` 네트워크 인터페이스의 주소로 인증서를 준비합니다. 여러 네트워크가 연결돼 있다면 다음처럼 Wi-Fi IPv4 주소를 직접 지정할 수 있습니다.

```bash
./웹실행.command --address 192.168.0.10
```

Wi-Fi 주소가 바뀌면 서버를 재실행해 새 주소를 사용하세요. 루트 인증서가 유지되는 동안 서버 인증서만 갱신되므로 휴대폰 인증서를 다시 설치할 필요는 없습니다. 인증서와 개인 키는 `.web-local/` 아래에만 있으며 웹 경로에서는 개인 키를 제공하지 않습니다. 이 폴더 전체를 다른 사람에게 전달하지 마세요.

## 새 웹 모드의 동작

- 입력 전 1초 대기는 없습니다. 최초 마이크 권한·연결 준비가 완료되면 입력합니다.
- 버튼을 누른 동안 들어온 음성만 사용합니다. 손을 떼기 전의 마지막 짧은 오디오 조각도 전송한 뒤 인식 요청을 마무리합니다.
- 손을 떼면 음성 인식과 목소리 분류를 실행합니다. 녹음 중에는 재생하지 않습니다. 한 번에 최대 10초까지 입력할 수 있습니다.
- 화면 전환, 터치 취소, 연결 종료, 전송 적체가 생기면 녹음을 중단합니다. 연결이 끊긴 요청의 뒤늦은 인식 결과는 새로 재생하지 않습니다.
- 웹 모드에서는 음원 간 의도적인 2초 대기를 없앴습니다. 한 입력 안의 같은 추임새는 한 번만 재생합니다. 새로 원을 누른 입력은 별도 요청으로 처리해 기존의 5초 반복 병합은 적용하지 않습니다.
- 한 입력에 서로 다른 추임새가 여러 개 있으면 순서대로 처리하되, 각 출력은 같은 말 끝 기준 3초 기한을 지켜야 합니다. 앞 음원이 길면 뒤의 음원은 기한 초과로 재생되지 않을 수 있습니다. 초기 검사는 **한 번 누를 때 한 추임새씩** 권합니다.
- 재생 중과 종료 직후에는 새 녹음을 시작하지 않습니다. 스피커 소리가 다시 입력되는 일을 막기 위한 동작입니다.
- 남성/여성 목소리 분류와 기존 인식 품질 기준은 유지합니다. 목소리가 불명확하거나 해당 음원이 없으면 재생하지 않으며 화면에 이유를 표시합니다.
- 원본 음성은 디스크에 저장하지 않습니다. 화면에는 인식 결과와 출력 예정 지연이 표시되고, Mac 터미널에는 출력 예정 시점이 표시됩니다.
- 기존 `실행.command`, 설정 파일과 터미널 모드의 동작은 바꾸지 않습니다.

## 3초 측정과 검토할 내용

1. **화면:** 원의 크기·색·움직임과 글자 크기가 휴대폰에서 편한지 확인합니다.
2. **누름:** 손을 떼면 휴대폰의 마이크 사용 표시가 종료되는지 확인합니다. OS의 사용 표시가 사라지는 애니메이션에는 시간이 조금 걸릴 수 있습니다.
3. **출력:** Mac의 원하는 스피커에서 올바른 추임새와 목소리 그룹의 WAV가 나오는지 확인합니다.
4. **응답 시간:** “얼쑤·좋다·잘한다”를 각각 여러 번 말해 3초 안에 실제 소리가 시작하는지 확인합니다. 실패·무응답도 함께 기록합니다. 마이크·스피커가 함께 녹음되는 별도 녹음으로 말 끝과 출력 시작을 비교하면 실제 지연을 확인할 수 있습니다.

앱은 연결 초기에 휴대폰과 Mac의 단조 시계를 동기화하고, 말 끝은 VAD로 추정합니다. 출력 예정 지연은 기존 Player의 PortAudio DAC 예정 시각을 사용합니다. 시계 동기화의 오차만큼 기한을 보수적으로 줄입니다. 시계가 동기화되지 않은 경우에는 Mac 수신 시각을 기준으로 한 추정이며 네트워크 지연이 완전히 포함되지 않습니다. 이 표시가 실제 스피커의 음향 지연을 보증하지는 않습니다. 특히 Bluetooth 스피커는 추가 지연이 생길 수 있으므로 초기 속도 검사는 Mac 내장 또는 유선 스피커로 진행하세요.

실제 Mac에서 모델 준비가 실패하면 오른쪽 위 연결 안내와 터미널에 오류를 표시합니다. `HF_HUB_OFFLINE=1 ./웹실행.command`로 실행하면 캐시된 모델만 사용합니다. 첫 모델 준비와 다운로드는 3초 응답 측정에 포함하지 않습니다.

## 개발 검사

```bash
.venv/bin/python -m unittest discover -s tests -q
node --test tests/web_client.test.cjs
node --check web/app.js
node --check web/pcm-worklet.js
```

Python 검사는 기존 로직과 웹 프로토콜·3초 기한·분류 라우팅을 확인합니다. JS 검사는 실제 앱과 AudioWorklet 코드를 Node의 격리된 브라우저 모형에서 실행해 녹음 종료·마지막 버퍼 순서·권한 대기 중 해제·화면 이탈·전송 적체를 확인합니다. 이 검사가 실제 Safari/Chrome 호환성이나 음성 인식 속도를 입증하지는 않습니다.

UI를 수정한 뒤에는 `.venv/bin/python web_make_preview.py`로 단독 화면 미리보기를 다시 만드세요.
