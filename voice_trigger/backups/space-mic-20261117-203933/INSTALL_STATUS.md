# 문장 속 추임새·연속 입력 정책 — 2026-11-17

- 기존에는 발화 전체 일치, 약 2.4초 초과 발화 제외, 같은 명령의 0.7초 쿨다운, 최신 인식 대기 하나만 보관하는 정책이었다. 서로 다른 명령을 기다렸다 재생하는 대기열은 없었다.
- 현재 활성 명령 세 개를 `match: "word"`로 바꾸었다. “아 이거 되는건가 얼쑤?”에서도 독립 단어 얼쑤를 찾고, 한 발화의 여러 추임새는 발화 순서대로 반환한다. `얼쑤라고`와 같은 단어 일부는 제외한다. 기존 `exact` 모드도 설정으로 선택할 수 있다.
- 같은 명령은 한 발화에서 한 번만 넣는다. 별도 발화라도 마지막 같은 입력 끝부터 다음 입력 시작까지 5초 미만이면 병합하며, 매 반복 때마다 시간을 연장한다. 해당 명령이 이미 재생 대기 중이면 시간과 관계없이 추가하지 않는다. 처음 수락한 목소리의 음원을 유지한다.
- 앞 음원의 DAC 예정 종료 시각부터 다음 시작까지 최소 2초를 둔다. 인식은 10초 안에 수락되어야 하며, 수락한 후보는 최대 60초 동안 재생 대기한다. 순차 재생 때문에 전체 출력은 발화 종료 후 10초를 넘을 수 있다.
- 마지막 말소리 뒤 0.6초의 무음과 진행·대기 인식 완료를 확인한 뒤 출력한다. 인식/재생 대기는 각각 최대 16개이며 먼저 들어온 순서를 보존한다. 긴 발화는 최대 약 5초씩 0.384초를 겹쳐 처리한다.
- 실제 음원 재생 중 및 종료 후 0.2초의 마이크 입력은 피드백 방지를 위해 계속 무시한다. 나머지 재생 사이 무음 구간의 입력은 받는다. 목소리 분류 불가·낮은 인식 품질·해당 음원 없음에는 출력하지 않는다.

검증:

- `.venv/bin/python -m unittest discover -s tests -q`: **51개 통과**. 문장 속 후보 추출, 순서, 반복 병합, 느린 인식의 대기열 보존, 긴 문장 분할, 출력 사이 새 입력, 실제 Player의 DAC 종료 기준 2초 간격, 10초를 넘는 수락 후보의 재생 대기를 검사했다. 마이크·STT를 대신한 제어 흐름 검사와 실제 출력 스케줄러의 가상 시간 검사다.
- 실제 실행 진입점의 `--test ... --voice male --no-play`로 예시 문장, 같은 추임새 3회, 서로 다른 추임새 3개를 각각 확인했다. WAV 6개를 실제 읽어 준비했으며 스피커 출력은 하지 않았다. 세 명령의 무음 재생 예약은 발화 순서대로, 시작 시각 차이 약 2.97초·2.94초였다(각 음원 길이 + 2초).
- `--doctor`: 패키지와 설정은 확인되었으나 이 작업 환경의 오디오 장치는 **0개**였다.
- `HF_HUB_OFFLINE=1 ... --prepare`: 캐시의 실제 목소리 모델을 불러왔으나 Whisper 준비 단계에서 **No Metal device available**로 종료했다. 네트워크 다운로드 없이 시도했다. 실제 마이크의 문장 인식률·스피커 간격은 이 환경에서 검증할 수 없었다.
- 변경 전 파일과 테스트는 `backups/utterance-queue-20261117-202635`에 보존했다.

적용: 실행 중인 프로그램을 Ctrl+C로 종료하고 `./실행.command`를 다시 실행한다. 이번 변경에 추가 모델이나 라이브러리 설치는 필요하지 않다. 자세한 정책과 설정은 README.md에 있다.

# 목소리 분류 기능 후속 상태 — 2026-11-13

- 여자·남자 추정에 따라 다른 음원을 고르는 코드와 설정을 추가했다. 얼쑤·좋다·잘한다 세 단어 및 남녀 WAV 6개가 연결되어 있다.

- **학습된 분류 모델 다운로드는 실패했다.** 이 도구 실행 환경에서 huggingface.co DNS 조회가 실패하여 가중치를 받지 못했다. 실제 목소리 판정은 아직 실행·검증하지 않았다.
- 인터넷이 되는 일반 터미널에서 `설치.command`를 실행하면 분류 모델 다운로드·준비 후 Whisper 준비를 수행한다. 다운로드 실패 시 다른 방식으로 대신 판정하지 않고 오류로 종료한다.
- 자동 검사 **35개 통과**. 목소리 그룹별 선택, 미확정/음원 없음 차단, 실시간 제어 흐름, NFC/NFD 경로, 모델 캐시/다운로드 실패 처리, 실제 Transformers API와 임의 가중치 소형 모델의 로드·추론 호환성을 확인했다.

# 설치·검증 상태

확인일: 2026-11-13

현재 설정: 사용자 요청으로 출력 시작 기한을 4초에서 10초로 늘렸다. 인식 완료 즉시 재생하는 방식은 유지한다. 설정 검증과 출력 안내도 10초 기준으로 변경했다. 아래의 4초 차단 기록은 변경 이전의 실행 기록이다.

## 후속 확인 및 속도 수정

- 이후 사용자가 실행한 세션의 로그를 확인했다. 현재 Silero VAD 6.2.3도 설치되어 있다. 아래의 설치 실패 기록은 최초 작업 당시 상태다.
- 실제 로그에서 ‘얼쑤.’가 수락되었지만 추론에 7.027초가 걸렸고, 발화 종료부터 결과까지 약 7.38초가 지나 deadline으로 재생이 차단되었다. 이 발화는 스피커 재생 요청까지 도달하지 않았다.
- 기본 모델을 mlx-community/whisper-small-mlx로 변경하고 word_timestamps를 false로 설정했다. 구간별 로그확률·무음·반복 검사와 4초 제한은 유지한다. 차단 이유를 터미널에 표시한다.
- 수정 후 자동 검사 21개 통과. 새 small 모델의 실제 속도·인식률은 아직 측정하지 않았다. 프로그램 재시작과 첫 모델 다운로드가 필요하다.
- 현재 도구 실행 환경의 GPU·오디오 접근 제한은 계속되어, 사용자의 실제 터미널 세션과 동일한 하드웨어 실행 검사를 이 환경에서 수행하지 못했다.

## 현재 상태

코드·설정·설치/실행 스크립트 작성과 자동 로직 검증을 완료했다. **라이브러리 전체 설치 및 실제 마이크 실행을 완료한 상태는 아니다.**

이 폴더에 Anaconda Python 3.13.5를 사용하는 `.venv`를 구성했다. Anaconda의 기존 라이브러리를 읽기 전용으로 재사용한다. 기본 환경의 패키지는 수정하지 않았다.

## 아직 완료하지 못한 항목

1. **Silero VAD 설치**: `설치.command`를 실제 실행했으나 pip의 PyPI 접속에서 `nodename nor servname provided, or not known` 오류가 발생했다. `silero-vad==6.2.3`은 아직 설치되지 않았다. 설치 스크립트는 실패를 표시하고 종료 코드 1을 반환했다.
2. **Metal 추론**: Whisper 프로세스의 실제 워밍업을 별도로 시도했으나 현재 실행 환경에서 `No Metal device available` 오류가 발생했다.
3. **오디오 입력·출력**: PortAudio가 현재 실행 환경에서 장치 0개를 반환했다. 실제 마이크와 스피커로 검증하지 못했다.

이는 현재 실행 환경에서 확인한 제한이다. 일반 macOS 터미널에서도 동일한 현상이 생기는지는 아직 확인하지 않았다. 인터넷 연결이 가능한 일반 터미널에서 `설치.command`를 실행한 뒤 `실행.command`를 실행해야 한다.
